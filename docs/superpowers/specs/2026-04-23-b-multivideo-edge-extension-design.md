# B 项目设计文档：Edge 多视频侧边栏扩展

## 1. 项目概述

`B` 是一个面向 `Microsoft Edge` 的浏览器扩展，目标是让用户把多个视频链接粘贴到扩展中，在 `side panel` 内统一管理和观看，最多同时维持 `6` 路任务。

第一版同时支持两类输入：

- 媒体直链：如 `mp4`、`webm`、`m3u8`
- 普通网页链接：扩展先静态解析，失败后再通过后台承载页做“尽力兼容”接管

产品优先级明确为：

- 兼容率优先
- 允许部分复杂站点只提供“后台运行 + 状态控制卡片”
- `side panel` 关闭后任务继续运行
- 浏览器重启后任务列表自动恢复，且自动尝试恢复播放

## 2. 目标

- 支持用户一次粘贴多条链接，按行拆分进入待确认列表
- 允许用户手动决定哪些任务开始运行
- 在扩展侧边栏中统一展示最多 `6` 路运行任务
- 对可直接播放的媒体源提供真实小窗播放
- 对无法稳定嵌入侧边栏的复杂网页链接，退化为后台承载页实际运行，侧边栏显示状态与控制
- 支持标准控制集：开始、暂停、停止、重试、删除、静音、音量、倍速、状态展示
- 支持关闭侧边栏后后台继续运行
- 支持浏览器重启后自动恢复任务和执行状态
- 为后续按域名扩展站点适配器预留架构插槽

## 3. 非目标

- 不承诺所有站点都可接入
- 不承诺复杂站点一定能在侧边栏显示真实视频画面
- 不支持 DRM 破解式兼容
- 不支持移动端浏览器
- 不支持跨浏览器适配，第一版仅面向 `Microsoft Edge`
- 不包含账号体系、云同步、远程任务同步
- 不包含高级布局编辑、字幕管理、画质切换、分组场景、时间轴拖拽等二期能力

## 4. 关键约束

- 平台：`Edge`，扩展形态为 `Manifest V3`
- 主界面：`side panel`
- 并发上限：最多 `6` 路活动任务
- 音频策略：全部默认静音，用户可手动开启某一路声音
- 权限策略：接受广泛站点权限 `http://*/*` 与 `https://*/*`，以换取更高兼容率
- 输入策略：用户通过多行粘贴提供链接，不做“从当前页面发送到扩展”的第一版入口
- 启动策略：链接进入待确认列表，用户点击开始后再运行
- 恢复策略：持久化任务列表并自动恢复播放

## 5. 用户流程

### 5.1 添加任务

1. 用户打开扩展 `side panel`
2. 在多行输入框中粘贴一个或多个链接
3. 系统逐行拆分、去空、去重、校验 URL 格式
4. 每条链接生成一条草稿任务，显示在待确认列表
5. 系统为每条任务进行初步分类：
   - 媒体直链候选
   - 普通网页链接候选

### 5.2 启动任务

1. 用户在待确认列表中选择单条或多条任务点击开始
2. 后台编排器为任务分配运行槽位
3. 任务进入解析流水线
4. 若可得到真实媒体源，则进入侧边栏真实小窗
5. 若只能通过网页接管运行，则进入后台承载页运行，侧边栏显示后台运行卡片
6. 活动任务总数达到 `6` 后，不再启动新的任务，剩余任务保持等待

### 5.3 运行中管理

用户可在运行卡片上执行：

- 开始
- 暂停
- 停止
- 重试
- 删除
- 静音
- 调整音量
- 调整倍速

### 5.4 关闭与恢复

- 用户关闭 `side panel` 后，后台任务继续运行
- 用户重新打开 `side panel` 时，界面根据持久化状态重建
- 用户关闭并重新启动浏览器后，后台编排器自动恢复任务列表并尝试重建原执行路径

## 6. 界面设计

`side panel` 分为 3 个主区域。

### 6.1 批量输入区

用于粘贴多行链接并提交到待确认列表。该区域展示：

- 多行输入框
- 提交按钮
- 批量清空输入按钮
- 基础格式提示

### 6.2 待确认列表

每条待确认任务显示：

- 原始链接
- 识别到的来源类型
- 域名或预估标题
- 预估执行方式：`侧边栏小窗` 或 `后台运行`
- 当前解析状态
- 开始、删除等操作

### 6.3 运行区

运行区最多展示 `6` 条活动任务，分成两类卡片：

- `真实小窗卡片`
  - 显示真实视频窗口
  - 显示播放状态、音量、倍速、错误状态
- `后台运行卡片`
  - 不承诺真实视频画面
  - 显示当前状态、域名、心跳、最近进度、控制按钮

## 7. 任务状态模型

任务状态统一由后台编排器维护，前端只订阅渲染。

建议状态集合如下：

- `draft`：刚创建，尚未开始
- `queued`：等待占用运行槽位
- `resolving`：正在解析和判定执行路径
- `ready_inline`：已具备侧边栏真实小窗播放条件
- `ready_background`：只能走后台运行
- `starting`：正在初始化执行器
- `playing_inline`：侧边栏真实小窗播放中
- `playing_background`：后台承载页运行中
- `paused`：已暂停
- `stopped`：已停止
- `error`：执行失败，可重试
- `unsupported`：确认不支持

该状态模型的目标是让用户始终知道一条任务是在：

- 正常小窗播放
- 正常后台运行
- 暂停或停止
- 本次失败但可重试
- 天然不支持

## 8. 系统架构

系统分为 6 个模块。

### 8.1 Side Panel App

职责：

- 渲染批量输入区、待确认列表、运行区
- 接收用户操作
- 订阅任务状态并更新 UI

非职责：

- 不直接承担复杂解析逻辑
- 不直接维护任务真值状态

### 8.2 Background Orchestrator

扩展 `service worker` 充当系统大脑，职责包括：

- 维护任务状态机
- 调度最多 `6` 个运行槽位
- 决定任务走 `inline` 还是 `background`
- 处理自动恢复
- 统一派发控制命令
- 汇总执行器回传的运行数据

### 8.3 Resolver Pipeline

解析流水线对输入链接做能力判定，顺序如下：

1. URL 基础分类
2. 直链特征识别
3. 静态探测
4. 页面接管价值判定
5. 选择执行模式

输出结果包括：

- 任务标题或候选标题
- 域名
- 预估播放方式
- 可用媒体源信息
- 不支持原因或降级原因

### 8.4 Inline Player Executor

处理可直接播放的媒体源，职责包括：

- 在 `side panel` 中创建真实小窗播放器
- 执行播放、暂停、静音、音量、倍速控制
- 回传播放状态、错误和结束事件

### 8.5 Hidden Page Runner

处理普通网页链接或复杂站点，职责包括：

- 为任务创建后台承载页
- 注入内容脚本探测和控制网页播放器
- 回传页面心跳、状态、错误和能力信息
- 在无法提供真实小窗时维持后台运行

### 8.6 Persistence Layer

持久化层负责保存：

- 任务列表
- 任务最近状态
- 用户控制参数
- 恢复所需元数据
- 站点能力探测结果缓存

## 9. 兼容策略

兼容层采用三级策略。

### 9.1 一级：静态解析

不打开页面，优先尝试：

- 识别直链媒体
- 分析 URL 与响应特征
- 从网页源码或显式嵌入信息中提取媒体源

命中后直接进入 `inline` 播放。

### 9.2 二级：通用页面接管

静态解析失败后，后台打开承载页，并由内容脚本尝试：

- 扫描 `<video>` 元素
- 识别常见网页播放器
- 监听播放、暂停、结束、报错
- 执行基础控制

若无法拿到可嵌入媒体源，但可以在页面内驱动播放，则降级为后台运行卡片。

### 9.3 三级：站点适配器

对于通用页面接管效果不稳定但用户价值高的站点，允许添加按域名加载的适配器逻辑，用于补足：

- 页面就绪判定
- 播放器定位
- 控制按钮触发
- 状态读取
- 特定错误识别

第一版要求预留适配器接口，但不要求覆盖大量站点。

## 10. 降级与错误模型

系统对失败结果做明确区分：

- `unsupported`
  - 例如 DRM、强沙箱 iframe、严格 CSP、无法注入控制逻辑
- `error`
  - 例如网络超时、页面初始化失败、播放器异常、内容脚本连接中断
- `degraded background`
  - 不是独立状态，而是执行结果说明：任务仍可运行，但只能显示后台运行卡片

设计原则：

- 优先保持任务“可运行”
- 无法给画面时也尽量保留控制能力
- 明确告知用户为什么没有真实小窗

## 11. 并发与资源控制

编排器采用固定槽位策略：

- 最多 `6` 个活动执行槽
- 待确认任务开始后，若无空槽则进入 `queued`
- 恢复时优先按上次活跃顺序重建
- 当浏览器资源压力过高时，优先保留成功率更高的任务，延后低优先级重试

此策略服务于两个目标：

- 保证“最多 6 路”的产品约束
- 避免恢复风暴导致全部任务同时失败

## 12. 持久化与自动恢复

恢复分为两层。

### 12.1 任务恢复

浏览器重启或扩展重载后，恢复：

- 任务列表
- 任务上次目标模式
- 用户设置的音量、倍速等参数

### 12.2 执行恢复

对每条任务尝试：

- `inline` 任务重建小窗播放器
- `background` 任务重建后台承载页与内容脚本连接

若连续恢复失败达到阈值：

- 不再无限重试
- 进入 `error`
- 由用户手动触发重试

## 13. 权限与安全边界

第一版接受较宽权限范围，以换取兼容率：

- `http://*/*`
- `https://*/*`
- 与 `side panel`、存储、标签页和内容脚本注入相关的扩展权限

此决定是有意的产品取舍：

- 若不接受广泛站点权限，“网页链接尽力兼容”无法成立
- 第一版优先验证任务模型和兼容策略，而非最小权限原则

## 14. 第一版范围

第一版必须实现：

- `Edge MV3` 扩展基础结构
- `side panel` 主界面
- 多行粘贴链接
- 待确认列表
- 最多 `6` 路任务
- 双通道执行：真实小窗与后台运行卡片
- 标准控制集
- 关闭侧边栏后继续运行
- 浏览器重启后自动恢复
- 静态解析与通用页面接管
- 站点适配器接口
- 基础错误分类与重试

## 15. 第一版明确不做

- 不承诺任意站点稳定可用
- 不承诺复杂站点总能显示真实视频画面
- 不实现 DRM 兼容
- 不实现高级布局编辑器
- 不实现字幕和画质管理
- 不实现云同步
- 不实现跨浏览器支持

## 16. 测试策略

测试按四层展开。

### 16.1 解析层测试

验证：

- 多行输入拆分
- 空行和重复链接处理
- URL 分类
- 静态解析命中与失败归因

### 16.2 编排层测试

验证：

- 最多 `6` 路并发
- 启动、暂停、停止、删除、重试
- 任务排队
- `side panel` 关闭后继续运行
- 浏览器重启后的自动恢复
- 恢复失败阈值后的收敛

### 16.3 执行层测试

验证：

- `inline` 小窗播放器基础控制可用
- 后台承载页内容脚本可连接、可回传心跳、可执行基础控制

### 16.4 兼容回归测试

准备样本池覆盖：

- 直链媒体
- 普通 HTML5 视频页面
- 常见嵌入式播放器页面
- 明确不支持样本

## 17. 验收标准

第一版达标的标准是：

- 用户能一次粘贴多条链接
- 任务先进入待确认列表，用户再手动启动
- 系统能同时维持最多 `6` 路任务
- 直链媒体能在侧边栏小窗中正常播放与控制
- 一部分普通网页链接能通过后台承载页运行
- 无法嵌入小窗时能稳定退化为后台运行卡片
- `side panel` 关闭后任务不中断
- 浏览器重启后，任务列表和执行状态可自动恢复
- 用户能从界面清楚分辨每条任务当前的执行模式与失败原因

## 18. 设计结论

第一版采用“兼容率优先的双通道架构”：

- 能拿到真实媒体源时，提供侧边栏真实小窗
- 拿不到真实媒体源但可在网页中驱动播放时，退化为后台承载页运行
- 通过统一任务编排器维持 `6` 路上限、后台运行和自动恢复

该方案不是最简单的实现，但与本项目已确认的产品方向完全一致，并为后续站点适配与兼容率扩展保留了清晰边界。
